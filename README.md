# OPUS Plugin Repository

The app store that OPUS reads on launch.

OPUS fetches **`catalog.json`** from this repository (branch `main`):

```
https://raw.githubusercontent.com/Denver062/OPUS-plugin/main/catalog.json
```

Every entry in the catalog can be installed from inside OPUS. OPUS downloads
`download_url`, unpacks the zip into `%APPDATA%\OPUS\apps\<id>\`, reads
`opus-app.json`, and then runs the app from there. Nothing is shipped inside the
OPUS executable.

## Layout

One folder per app, holding both what OPUS installs and what it shows before
installing:

```
catalog.json                          # the list OPUS downloads
apps/<id>/
  app/opus-app.json                   # installer manifest (source of truth)
  package/<id>-<version>.zip          # downloadable package: opus-app.json + entry
  preview/preview.json                # store page text (tagline, about, changelog)
  preview/icon.png                    # optional app icon
  preview/screenshot-1.png            # optional screenshots
```

`catalog.json` is generated by `publish-plugin.ps1`; each entry points at the
files above and embeds the preview text so OPUS can render a card without a
second request.

## Package rules

A zip is unpacked straight into `%APPDATA%\OPUS\apps\<id>\`, so its contents
must sit at the **root** of the zip:

```
schun-aod-1.0.0.zip
  opus-app.json
  schun.scr
```

* `opus-app.json` must declare `id`, `name`, and `entry`.
* `entry` is relative to the app folder. It is used for `commands.start`,
  `commands.install`, and `commands.uninstall` defaults.
* Settings are declared in `settings.fields` and rendered by OPUS. See the
  [app SDK](https://github.com/Denver062/OPUS#app-development-guide).

## Preview (before install)

`preview/preview.json` describes the app in the OPUS store:

```json
{
  "tagline": "One line shown under the app name",
  "about": "The store page body. Describe what the app does and what makes it useful in a few sentences of normal prose - no bullet lists.",
  "changelog": "1.0.0 - First public release.",
  "icon": "icon.png",
  "screenshots": ["screenshot-1.png"],
  "released": "2026-11-09"
}
```

* `about` is the only place features are described; OPUS shows the first few
  lines on the card and the rest behind **More**.
* `icon` and `screenshots` are file names inside `preview/`. Leave them empty
  and the publisher picks up `icon.png` and `screenshot-*.png` automatically.
* `released` defaults to the publish date when omitted.
* `size_bytes` is filled in by the publisher from the generated zip.

The same content ends up in the catalog as a `preview` object with absolute
`icon_url` / `screenshots` URLs, which is what OPUS displays.

## Edu apps

Set `"edu": true` in the app's `opus-app.json` for apps made for schools. OPUS
shows an **Edu** tag on the app card and can filter the store down to Edu apps.
The flag is copied into the catalog as `"edu": true`.

## Adding an app

1. Create `apps/<id>/` with `app/opus-app.json`, `package/<id>-<version>.zip`,
   and a `preview/` folder.
2. The published catalog entry looks like this (regenerated for you by
   `publish-plugin.ps1`):

```json
{
  "id": "my-app",
  "name": "My App",
  "description": "What it does",
  "version": "1.0.0",
  "author": "You",
  "category": "utility",
  "edu": false,
  "repo_url": "https://github.com/you/my-app",
  "download_url": "https://raw.githubusercontent.com/Denver062/OPUS-plugin/main/apps/my-app/package/my-app-1.0.0.zip",
  "preview_url": "https://raw.githubusercontent.com/Denver062/OPUS-plugin/main/apps/my-app/preview/preview.json",
  "preview": {
    "tagline": "What it does",
    "about": "Longer paragraph for the app.",
    "changelog": "1.0.0 - First public release.",
    "icon_url": "https://raw.githubusercontent.com/Denver062/OPUS-plugin/main/apps/my-app/preview/icon.png",
    "screenshots": [],
    "size_bytes": 2267402,
    "released": "2026-11-09"
  }
}
```

3. Commit and push to `main`. OPUS picks the change up the next time the
   Download tab is refreshed.

## Releasing a new version

Bump `version` in the app's `opus-app.json`, then run `publish-plugin.ps1` from
the OPUS source tree. It repacks the app into `apps/<id>/package/`, refreshes
`app/` and `preview/`, rewrites `catalog.json`, and pushes. Older zips of the
same app are removed, so the repository stays small.

OPUS compares the catalog version against the installed manifest version and
shows an **Update** button when they differ.

```powershell
powershell -ExecutionPolicy Bypass -File publish-plugin.ps1
```
